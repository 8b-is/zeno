Google Wallet setup · click-through

For Alexandra · about 20 minutes · two things come out of it: a number and a file.

The goal in one sentence

Google has to be told who we are (the long Issuer ID number) and be given a robot key (a small JSON file) so our server can sign ZENO passes. Nothing else is needed. No card numbers, no bank login.

Two rules, no exceptions

  • Never paste the JSON file (or any client_secret) into email, GitHub, this chat, or a doc.
  • If a secret ever lands somewhere public: Console → Service Accounts → Keys → delete, and tell Péter. Thirty seconds, no damage.

0Before you start

  • Chrome on a laptop (phone works but the console is cramped).
  • Signed in as the Google account that owns the Cloud project zeno-wallet-512901.
  • A notes app open for one number.

1Open the Wallet console and accept the terms

Open Pay & Wallet Console ↗
  1. Sign in with that same Google account.
  2. First time only: read the terms → click Accept / Get started.
  3. If it asks for a business profile: name ZENO, country Japan, website https://zeno.vaked.dev.

2Copy the Issuer ID — this is the number

On the console home (or under Account settings) there is a card labelled Issuer ID. It is 19–20 digits, starts with 3388….

  1. Click the copy icon next to it.
  2. Paste it into your notes as ZENO issuer id.

If you see no Issuer ID, the terms in step 1 were not accepted yet. Go back, accept, refresh.

3Flip the API breaker

Open Google Wallet API ↗
  1. If the button says Enable, click it. Wait ~15 seconds.
  2. It should now say API enabled / Manage. That is all — nothing to configure.

4Create the robot key — this is the file

Create service account ↗
  1. Service account name: zeno-wallet-signer → Create and continue.
  2. “Grant this service account access” → just Continue (no role needed).
  3. “Grant users access” → Done.
  4. In the list, click the new row ending in @zeno-wallet-512901.iam.gserviceaccount.com.
  5. Tab Keys → Add key → Create new key → choose JSON → Create.
  6. A file downloads. Rename it to google-wallet-sa.json. This file is the key to the vault.

If the browser blocks the download, allow it once and repeat “Add key”.

5Introduce the robot to the Wallet console

  1. Back on the console → left menu → Users → Add user.
  2. Paste the robot email zeno-wallet-signer@zeno-wallet-512901.iam.gserviceaccount.com, role Admin (or Developer) → Invite / Save.
  3. On the same page, add your own Google email under Test accounts. Without this, passes will not install on your phone while testing.

Skip the robot step and everything looks fine until Google silently rejects our signature.

6Hand the two things over — safely

Pick one channel, in this order of preference:

  1. 1Password: vault VAKED Ops → new item Google Wallet SA → attach the JSON, paste the issuer ID in the notes → share with Péter.
  2. AirDrop the file to Péter's Mac, then send the number in Signal.
  3. Signal / in person — file and number, never in the same public place.

Do not email it. Do not put it in a shared doc. Do not paste it in any chat, including this one.

7How you know it worked

Péter runs two commands and redeploys. Then this URL stops saying unconfigured and starts returning a pass link:

https://zeno.vaked.dev/api/wallet/google-pass

Open the returned link on the phone → Add to Google Wallet. That is the finish line.

Troubleshooting, exact words → exact fix

What you seeWhat it means
unconfigured stillOne of the two things did not reach the server. Re-check step 6.
“Caller is not authorized” on saveRobot email not added in step 5.
Pass saves but will not installYour email missing from Test accounts (step 5.3).
No Issuer ID anywhereTerms not accepted (step 1.2).
Add key greyed outYou are not Owner/Editor on the Cloud project. Ask Péter to grant it.
